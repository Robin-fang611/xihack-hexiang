# 合香本机软件

本项目是可运行的本机合香探索与定制原型，包含私人香品分析、创作者（OPC）作品与商品发布、自由调香、个人香笺和软件空间模拟。入口为 [本机软件](http://127.0.0.1:8870)；[双端口演示](http://127.0.0.1:8875) 使用 `app/.demo/` 隔离虚构演示数据（双击 `启动演示.command`，凭据见 `.demo/演示说明.txt`）；[隔离预览](http://127.0.0.1:8873) 使用自建临时资料。当前只监听本机，尚未对外部署。

## 双端口：消费者端与 OPC 创作者端

2026-10-03 双端口迭代（分支 `feature/dual-portal`）把界面组织为两个端口，进站先见「端口大厅」：

- **消费者端（香事体验，免登录）**：大厅左门进入。首页「设计起点」并列三炉草案与创作者作品（标注创作者名、可一键以此起稿），「现成香」区展示创作者上架商品并带购买入口；调香案、图鉴、我家的香、空间接入不变。
- **OPC 创作者端**：大厅右门进入，未登录见入驻引导，注册时选择「创作者入驻」即可开通。工作台汇总作品/商品/已发布数量；「我的作品」把调香案保存的构图发布为首页设计起点（公开名称、场景、构图、方向与署名 + 可选创作说明）；「我的商品」保留原有上传→分析→自选公开字段→挂首页能力。
- **隐私边界**：作品公开投影只含设计事实与署名；用户原话（user_notes）、原始偏好文字与私人附件永不公开（HTTP 验收断言）。购买在商家渠道完成，平台不做支付或订单。

服务端对应变化：注册接受 `account_kind:"creator"`（内部 role=manager，文档定义的管理者/开发者同类权限）；`POST /api/designs/{id}/publish|unpublish` 发布/撤下作品；`/api/bootstrap` 新增 `works` 白名单投影。详见 [API契约](<./API契约.md>)。

2026-10-03 的五轮连续迭代已完成，各轮均有实际产品改动、真实验收和正式收据。`iteration_cycle.py status` 已核对 `completed_rounds=[1,2,3,4,5]`、`active_round=null`、`status=complete`，详情见 [产品开发计划](<产品开发计划.md>)。下文区分当前能力、历史验收与尚未验证的业务边界。

两处入口已重启并加载当前源码，OCR 能力可用，两服务各 29 份静态运行文件的 HTTP 内容 SHA256 与当前源码一致。原 8870 的 12 份资料文件和两个 SQLite，隔离 8873 的三份资料文件和一个 SQLite，重启前后文件指纹、大小、权限、各表内容摘要与数据库完整性均一致；核对未创建正式会话。证据为 `verification/iterations/最终运行核验/重启与完整性.json`。

## 本轮产品与开发安排

完整的 14 项任务、依赖、四批开发节奏与状态见 [产品开发计划](<产品开发计划.md>)。首页现有三份参考设计与香事插画，调香支持场景挑卡、三香盘、进度提示、偏好互斥和撤回；素材由 AI 辅助代码绘制，未使用网络图片或外部字体。

14 项升级时前端拆为 9 个 ES 职责模块和 7 个 CSS 模块；五轮迭代后新增原话提案、草稿和迭代样式，当前为 11 个 ES 职责模块和 11 个 CSS 模块。账号/请求代次与共享 Cookie 身份核对保护私人资料，设计版本保护候选和香笺；场景或原话改动后需重新生成，预设不会取消已选排除。实际 PNG 使用导出快照，长文按内容增高。SQLite 表结构未迁移。

## 怎样进入

普通用户在界面注册账号即可。管理者使用同目录 `.local/本机管理者账号.txt` 中首次启动生成的账号；文件仅本人可读、未进入版本控制，网页接口不会返回凭据。两种角色共用香品分析，只有管理者能将自己的商品放到首页。

首页最初没有实体商品。管理者上传真实资料、选择公开字段并挂上首页后，普通用户才能看到；软件不会把设计草案伪装成在售商品。管理员也能用“我家的香”保存自己的私人咨询。

## 已有功能

- 登录注册、密码散列、会话、服务端角色与资料归属校验。
- 照片、文字、PDF、Word资料上传及本机文字提取；成分声明、香调描述、实闻与系统归类分开。
- 本人私人档案，管理者商品档案，以及公开字段、独立公开图片、商家链接和撤下。
- 材料卡点击、拖拽或 44px 快捷按钮入案；主调、支撑、点缀三个位置，主调锁定、排除、差异候选、回退和草案入口。一个合法主调也可形成参照香笺。
- 按本机已有词表整理明确原话，先展示原句、条件提案、冲突和未知，再由用户应用；应用后的条件影响真实候选。复杂否定和未收录意象保留为未知。
- 本标签页 `sessionStorage` 草稿接续，保留构图、偏好、排除、场景、原话、主调锁定和名称；不恢复旧候选、旧核验香笺或模拟。退出、401 和账号变更清理本页私人草稿；非法或过期资料整份拒绝，原始草稿留待恢复。
- “保存到我的香笺”与“下载 PNG”独立。保存需要登录，界面对已知已保存签名不重复发送请求，直接重复调用 API 时同账号相同核验设计返回原记录和 HTTP 200；PNG 在浏览器按当前香笺快照绘制，无保存请求，未登录或保存失败后仍可下载。已存作品仅查看不覆盖案头，点击“回到案头继续”才接续为新草稿。
- 图鉴分传统材料、现代参照、历史香方与文化规则。名称和资料标签筛选仅用于现代参照；现代具体形态可带回案头，传统同名原料和历史原名不会直接成为混配材料。现成香匹配只使用首页公开商品资料。
- 软件模拟经服务端交接与确认后可设 1–120 整数分钟、开启、关闭或查状态。服务端用单调时钟与后台定时器到时自动停止，关闭浏览器后仍计时；界面只在收到后台状态后确认停止。
- 商品修改、挂首页和撤下携带 `revision`；旧版本返回 HTTP 409，保留文字、链接、价格与公开字段选择，读取最新内容对照后再保存。迟到的列表响应也不会覆盖正在编辑的发布表单。
- 私有请求携带页面预期账号，Cookie 已在另一标签页换号时拒绝回填新账号的私人内容；页面重新获得焦点或可见时也核对账号。注销、登录替换会话时撤销旧模拟，注销中的迟到交接不能重建旧实例。

草稿属于浏览器本标签页，关页后的留存由浏览器会话机制决定；它不是长期作品备份。要长期保留请登录保存或下载 PNG。改变案头或模拟场景会取消本页操作确认，后台旧模拟状态不会被这个动作直接改写；重新交接会替换同会话旧实例。计时依赖本机服务持续运行，服务重启后需重新交接和确认。

## 分析和验证范围

图片使用本机Apple Vision识别文字，文字归类与调香使用有来源的知识规则。本版没有调用外部大模型、付费接口或网页抓取，不反推秘密配方、浓度和投料比例。PDF提取前5页可读取文字；扫描PDF可改传照片。单份附件上限8MB，照片支持PNG、JPEG、WebP。

真实气味、制造、实际耗材与设备、商家成交及生产环境尚未验收。普通上传与未选公开字段不会进入首页；明确排除条件缺少产品成分依据时，匹配结果不会保证满足。

## 运行与存储

本机可双击“启动软件.command”，或用Codex现有Python运行库执行 `server.py`。没有安装新依赖，复用运行库中的Pillow、pypdf与macOS原生OCR。静态界面不依赖外部字体、脚本或CDN。

账号、会话、私人资料、图片和设计保存在 `.local/`，该目录已忽略，不随源代码打包。重启不会清空资料。不要把这个目录与账号文件放到公开仓库或参赛公开包；脱敏后的证据使用 `verification/`。

## 重复执行软件验收

在 `app/` 下，用已有运行库执行完整原有回归：

```sh
../.venv/bin/python verify_v2.py   # 无虚拟环境时用 python3 verify_v2.py
```

脚本依次执行 HTTP、数字调香、知识反例、浏览器回归，并启动自动分配端口的临时服务；结束后清理该临时数据库和服务，不操作原 `.local/`。复用现有 Node、Playwright、Chrome 和 Python 库，缺少运行库时报告问题，不自动安装。

14 项升级的历史结果在 `verification/v2/`：9 组 HTTP、29 项数字调香、8 类知识反例、12 组浏览器流程通过，包含 48 项布局检查；无脚本错误、请求失败或静态 404。`整体验收.json` 记录当时源码 SHA256。`交互补充验收.json` 另记实际键盘、拖拽与 600 字中文导出，截图和实际 PNG 已目视核对；这部分为当时补查，不包含在一条命令的 12 组流程中。原入口在该阶段曾重启，12 份原运行文件 SHA256 一致，记录在 `verification/v2/原入口与资料完整性.json`，不替代五轮后的重启核对。

当前五轮的组合行为检查使用 `test_iterations.py --round 5`，自动建立隔离临时资料与端口，覆盖前四轮能力、第五轮新增边界、真实一分钟后台停止和适配保存/确认语义的原有完整回归；结果保存在 `verification/iterations/round-5/`，完成计轮后的不可变收据在 `round-05/completion/`。不要同时启动两份该检查，也不要在运行中修改被测源码。
